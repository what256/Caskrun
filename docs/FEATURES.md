# Feature inventory

Caskrun aims to cover the **publicly documented CrossOver Mac workflows** with original code and independently licensed runtimes. This checklist is a requirements map, not a claim of compatibility or parity. It draws on public CodeWeavers documentation only; CrossOver code, assets, installer recipes, and bundled runtime do not belong in this project.

Statuses distinguish source implementation from installer, client, authentication and game validation. **Present in source** means a code path exists. **Partial** means only part of the workflow exists. **Planned** means no implementation exists. The current local candidate contains an ARM64 SwiftUI app/core and independently built Wine 11.0 with GnuTLS, original Steam CEF/Dock changes and general per-executable native identities. Its source and runtime receipts accompany the ignored development package; it remains ad-hoc signed.

Home retains compact bottle folders, smaller app/game icons and its right inspector. The floating capsule has Home, Library, Discover and a + menu, with optional search through Command-F. Library combines local installed-game manifests, saved apps and browser shortcuts. Discover separates eight experimental Windows installers, external game reports and browser games. The included engine is selected automatically, with no global Settings page or Wine picker. The inspector retains optional bottle, app, display, tool and maintenance controls.

Earlier user-led Steam tests reached a usable sign-in window and one working Dock icon, with intermittent black relaunches and reported low visual quality. High Resolution passed isolated registry/API probes and later sharpness measurements on Steam and Wine builtin windows; DPI-unaware installers can remain upscaled. It stays optional and off by default. The October round completed GOG, Battle.net, Ubisoft and itch.io setup but found unusable clients; Epic's MSI failed and EA was closed at its agreement. Rockstar setup started but window inspection was blocked; its test was canceled and cleaned. Authentication and gameplay remain untested. The [launcher validation record](LAUNCHER_VALIDATION.md) is the current stage-by-stage evidence; older smoke results below retain their original scope.

The preceding maintenance phase passed 375 Rust unit tests and 6 integration tests, with 2 existing tests ignored; 97 Python checks and 10 Swift argument checks also passed. The library phase adds focused browser privacy, compatibility-data, manifest-discovery and Steam-install-request checks. The optional [DXMT controls](DXMT_OPTIONS.md) have a separate passing original x64/x86 API matrix; [app integration](DXMT_APP_INTEGRATION.md) retains its loader, rendering and migration evidence. See [maintenance workflows](DEMO_MAINTENANCE.md) and the [manual checklist](MANUAL_TEST_CHECKLIST.md). Source and graphics API tests do not establish app/game compatibility. The [implementation plan](COMPATIBILITY_PLAN.md) describes remaining work, while [UI smoke](UI_SMOKE.md) records earlier visual/navigation checks.

| Signed, notarized app and DMG | Partial | A local ad-hoc signed app and self-contained development DMG build and verify. Developer ID signing, notarization, public distribution, and a release-ready source/license audit are absent. |
| Original shareable compatibility reports and installation recipes | Partial | A locally saved, privacy-limited diagnostic report exists. It contains no game acceptance results and is never uploaded automatically. Community compatibility publishing and recipe updates remain absent. |

## Release gates

1. **Working baseline:** an independently sourced Wine runtime starts; Caskrun initializes a real bottle, installs a small unlisted EXE and MSI, waits for completion, shows logs, and relaunches the installed program.
2. **Catalog workflow:** Steam and other supported entries get original, tested installation recipes, verified download sources, dependency handling, cancellation, and honest compatibility notes. Users can still choose any local installer.
3. **Bottle and app management:** implement and test launcher discovery, bottle lifecycle actions, backup/restore, and diagnostics above.
4. **Compatibility and release:** test Apple Silicon, including Windows x86/x64 apps, macOS integration, graphics/input options, accessibility, dependency licensing, signing/notarization, and DMG installation. Mark a row **Validated** only with repeatable evidence.

## Explicit non-goals

- No CrossOver trial, purchase, activation, account, or license-expiry flow. Caskrun is a separate open-source product.
- No assertion that public documentation lists every internal CrossOver feature or that Caskrun can run every Windows app. Compatibility depends on the runtime, macOS, hardware, and the application.
